  🔴 P0 — 确认的真 Bug（建议优先修）

  这些会产生用户可见错误或损坏数据。前 4 项我已独立复核确认。

  1. 填空题题干含数字会渲染错乱 src/lib/quiz/parse-quiz.ts:96
  Number(segment) 把"两个 gap 之间的纯数字文本"误判为 gap
  占位符。如填空题正文夹了裸数字（且值落在空数量范围内），该数字会变成空白输入框
  、原文丢失。触发窄但静默。
  → 哨兵改为 \x00GAP{n}\x00，用 /^GAP(\d+)$/ 精确匹配整段，而非对任意段做
  Number()。

  2. 行内标记后的 {...} 被静默吞掉
  src/lib/markdown/remark-shoka-effects.ts:74（spoiler 同款）
  ++完成++{待办} 渲染成 <ins>完成</ins>，{待办} 被无条件删除。原因：无论 {...}
  是否为有效属性块，lastIndex 都推进消费了它。
  → 仅当 buildAttrString 解析出有效属性时才消费 {...}，否则当普通文本保留。

  3. 解密重入导致交互元素重复绑定
  src/components/common/CustomContent.astro:125-151
  解密完成会移除 data-enhanced 并重跑 enhanceContent()，但
  tab/spoiler/anchor-link 三段是裸 addEventListener 无去重（媒体增强器都有
  WeakSet 去重，唯独这三段没有）。anchor-link 几乎每篇文章都有 →
  解密后点击标题锚点 pushState 两次；spoiler 双绑定会 toggle
  互相抵消（点击失效）。
  → 加 if (el.dataset.koharuBound) return; el.dataset.koharuBound='1'
  守卫，或改事件委托。

  4. 空分类页渲染字面量"0" src/components/category/CategoryPostList.astro:46
  {posts?.length && (...)}，空数组时 0 && ... 返回 0，Astro 把数字渲染成文本。访
  问"只有子分类、无直属文章"的分类页会看到孤立的"0"。（该文件正在改动中）
  → 改 posts.length > 0 && (...)；line 37 的双重 ?.children?.length
  冗余可一并清理。

  5. 圣诞灯 visibilitychange 监听器确定性泄漏
  src/components/layout/ChristmasLights.astro:22-38
  每次 astro:page-load 都 addEventListener('visibilitychange', 
  新闭包)，无移除。客户端导航 N 次后挂 N 个回调。
  → handleVisibility 提到模块顶层，绑定前先 remove，或加 flag 只绑一次。

  6. 相似度生成：空文本产出"全 0 相似度"坏数据
  src/scripts/generateSimilarities.ts:268
  当 INCLUDE_BODY=false（默认）且某文 description 为空，嵌入文本退化为 "标题. 
  "；零范数向量 normalize 原样返回，与所有文章点积恒为 0 →
  该文静默获得"按数组顺序前 5 篇"的错误相关文章。
  → 对零范数向量 console.warn 提示 slug，单篇嵌入失败用 try-catch
  剔除而非静默写入。

  7. OG 描述可能整段变空 src/lib/sanitize.ts:96（extractTextFromMarkdown）
  手写字符级状态机里 ::: 容器深度判定用 line.length > 3 当"打开"，但带尾随空格的
  ::: （长度 4）或嵌套会让 depth 永久失衡，吞掉后续正文 → OG/描述静默变空。
  → 此函数是纯构建期，无微优化必要；建议用项目已有的 remark+strip-markdown
  重写，或至少修正 ::: 配对（line===':::' 判关闭）。
